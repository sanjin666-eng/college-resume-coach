# 阶段二：纯文字简历

## 输入门槛

使用用户确认的《个人经历梳理》、原始简历或等价完整材料。若基础联系方式、教育时间或关键经历时间缺失，在生成前集中询问一次；用户暂不提供时保留 `【待补充】`。

本阶段只生成纯文字简历，不生成 HTML。先给出简短的整体优化说明，再生成可下载的 Markdown 文件，等待用户确认。

本阶段的正式产出必须是 `{姓名}-简历文字版.md`；姓名未知时使用 `简历文字版.md`。不要只在对话中展示文本来替代文件。

## 固定模块顺序

1. 个人联系信息
2. 求职意向
3. 教育经历
4. 实习 / 工作经历（含全职、个人创业）
5. 项目经历
6. 校园经历
7. 技能与荣誉

无内容的模块直接删除，不展示空标题。竞赛和奖项通常归入教育经历的荣誉或技能与荣誉；只有过程足够完整、能作为项目叙述时才可进入项目经历。志愿经历按内容归入校园经历或项目经历。

## 改写硬规则

- 只使用用户确认的真实信息。缺失普通事实标记 `【待补充】`，缺失量化指标标记 `【待补充量化数据】`。
- 删除空话、抒情和主观自我评价，不写“提升能力、锻炼思维、积累经验”等成长感悟。
- 聚焦执行动作、工具/方法、交付物、客观成果和数据指标。
- 使用正式、干练的商务表达，避免夸张修饰和 AI 式总结。
- 不重复同一成果，不把团队总体成果表述为用户个人成果；需注明个人负责范围时明确写出。

## 模块写法

### 教育经历

包含学校、专业、学历、起止时间；海外交换/访学单独标注。精简列出与经历相关的核心课程、GPA/排名（仅用户提供时）和奖学金、竞赛、荣誉。

### 实习 / 工作经历

头部格式：`公司名称｜岗位｜起止时间`

每条要点以动词或加粗逻辑标签起笔，按“行动 + 工具/方法 + 交付物 + 客观结果”组织。可使用调研、访谈、搭建、策划、输出、对接、统筹、推广、分析、验证、招募、整理、归档、主持、落地、优化、复盘等准确动词，但不要为套动词而扭曲事实。

可按事实选择前期调研、方案策划、落地执行、内容搭建、数据复盘、活动推广、体系优化等逻辑标签。优先呈现样本量、访谈人数、文档/物料数量、活动场次、参与人数、覆盖范围等用户确认的指标；没有业务数据时突出交付物和流程成果。

### 项目 / 校园经历

沿用实习经历的证据标准，聚焦事务统筹、活动组织、团队协作、内容运营、执行落地和数据整理等实际工作，避免与实习模块重复。

### 技能与荣誉

按专业技能、软件工具、语言能力、证书荣誉分类。语言写明用户提供的等级；技能熟练程度只有用户提供明确依据时才写。

## 输出结构

### 第一部分：简历优化整体说明

用简短条目说明原始材料的主要问题、采取的优化方向和可验证的升级亮点。不要进行 JD 或岗位匹配分析。

### 第二部分：纯文本完整版精修简历

完整输出简历文本。时间统一为 `YYYY.M–YYYY.M`；并列字段顺序一致；所有待补充标记保留。

将这一部分连同必要的文档标题写入正式 `.md` 文件。该文件是第三阶段 HTML 的内容唯一来源。用户确认后，锁定其中的简历正文；第三阶段不得为了版面删减、缩写、合并、润色或改写。

### 第三部分：待确认清单

列出：

- 仍缺失的事实与量化指标；
- 为控制篇幅而合并或建议删减的内容；
- 需要用户确认的分类或表述。

用户确认 `.md` 文件后，再进入阶段三。若用户有修改意见，先更新完整 Markdown 文件并再次确认。进入阶段三后先忠实排版；排版完成后如用户主动提出文字调整，再按其具体意见修改 Markdown 与 HTML，保持二者一致。
