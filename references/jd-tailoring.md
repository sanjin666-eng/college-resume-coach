# 独立模块：根据岗位 JD 定制简历

## 模块定位

本模块与“从零制作简历”的前三阶段相互独立。用户可以跳过访谈、经历梳理和母版简历生成，直接用已有简历进行岗位定制。

只有以下两项是必需输入：

1. 完整岗位 JD；
2. 初版简历。

初版简历可以是本 Skill 生成的 Markdown 或 HTML，也可以是用户直接提供的 Markdown、Word、PDF、HTML、纯文本或其他可读取格式。已有材料能够读取时直接使用，不要求用户重新粘贴或重新走前三阶段。缺少 JD 或初版简历时，只询问缺少的那一项。

## 事实边界

- 初版简历和用户在本模块中补充确认的信息，是定制简历的唯一事实来源。
- 可以删除低相关内容、调整同一经历内的要点顺序、重组句子，并自然融入与事实相符的 JD 关键词。
- 不得编造工作内容、项目职责、工具、技能、证书、奖项、数据或业务成果。
- 不得把团队成果写成个人成果，不得把“了解、接触、使用过”升级为“精通、主导、负责”。
- 对 JD 有要求但简历没有证据的内容，标记为“材料未体现”，不能代替用户补写。
- 永远保留初版简历原文件；定制版本使用新文件名，不覆盖母版。

## 工作流程

### 第一步：检查输入

确认已获得完整 JD 和可读取的初版简历。提取公司、岗位、地点、岗位职责、任职要求等信息；无法从 JD 确认的字段标记 `【待补充】`，不猜测。

### 第二步：拆解 JD

将要求分为：

- 核心工作任务；
- 必备能力与工具；
- 优先条件；
- 行业、业务和岗位关键词。

不要输出没有可靠依据的百分制“匹配度”。每项要求使用以下判断：

- `明确匹配`：初版简历中有直接事实或成果证据；
- `部分匹配`：有相近经历，但职责、工具或结果证据不完整；
- `材料未体现`：初版简历及用户补充信息中没有相关证据。

### 第三步：建立证据映射并补充提问

建立“JD 要求—简历证据—判断—处理方式”映射。只针对会明显影响本岗位定制效果的高价值缺口提问，一次集中询问，避免重新进行完整经历访谈。

用户没有相关经历或不愿补充时，保留缺口并继续；不得暗示其认领建议答案或虚构数据。

### 第四步：生成定制简历文字版

允许：

- 将求职意向改为 JD 对应岗位；
- 选择并保留与 JD 更相关的经历和技能；
- 删除与岗位明显无关的低价值内容；
- 调整同一段经历中要点的先后顺序，让强匹配证据优先；
- 在不改变事实的前提下重组表达，使用 JD 中与事实相符的关键词；
- 优先呈现可验证的行动、工具、交付物和量化成果。

同一内容模块内的完整经历块，继续遵循 HTML 规范中的开始时间排序规则；岗位相关性通过内容取舍和经历内部要点顺序体现，不通过打乱经历时间顺序体现。

正式交付两个 Markdown 文件：

1. `{姓名}-{公司}-{岗位}-JD匹配分析.md`
2. `{姓名}-{公司}-{岗位}-定制简历文字版.md`

匹配分析文件应包含 JD 拆解、证据映射、材料缺口和本次定制策略。定制简历文字版应是可以直接投递前审核的完整简历，不夹带分析说明。

交付后明确请用户审核定制文字版。用户未确认前不得生成或修改定制 HTML。

### 第五步：确认后生成定制 HTML

用户确认定制简历文字版后，读取 [可编辑 A4 HTML 规范](html-resume.md)并生成：

`{姓名}-{公司}-{岗位}-定制简历.html`

HTML 必须逐字采用用户确认的定制 Markdown 正文，不得在排版过程中再次删减、缩写、合并、润色、改写或补充。先完成排版并交付，再根据用户主动提出的修改建议迭代。

若单页无法容纳，先调整间距、行距和字号；达到可读性下限后仍无法容纳，则保留完整文字并让用户选择删减内容或接受多页。未经明确同意不得自行删除。

## 模块结束条件

只有在以下条件全部满足后，本次 JD 定制才算完成：

- 匹配分析 Markdown 已交付；
- 定制简历文字版 Markdown 已由用户确认；
- 定制 HTML 已生成并通过浏览器排版检查；
- HTML 与确认版 Markdown 正文一致；
- 初版简历和母版文件未被覆盖。
